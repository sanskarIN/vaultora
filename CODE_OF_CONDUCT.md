# Vaultora Code of Conduct

## Our standard

Vaultora should be a constructive, safe and technically rigorous open-source community. Participation is welcome regardless of experience level or background when contributors interact respectfully and in good faith.

Expected behavior includes:

- discuss ideas and code without attacking people;
- give specific, actionable review feedback;
- accept correction and update claims when evidence changes;
- respect privacy and never request or expose another person's real vault data or credentials;
- avoid harassment, threats, discriminatory language, sexualized attention, doxxing, spam and deliberate disruption;
- disclose conflicts of interest that could reasonably affect security or dependency recommendations;
- follow coordinated vulnerability-disclosure rules for security findings.

## Security-sensitive discussions

Do not post working exploit details, real credentials, private vault files or other material that could unnecessarily put users at risk in a public issue. Use [SECURITY.md](SECURITY.md) for vulnerability reports.

## Scope

This policy applies to repository issues, pull requests, discussions, code review, project-linked community spaces and direct project communication when someone is acting as a Vaultora participant or representative.

## Enforcement

Maintainers may edit or remove abusive or unsafe content, close discussions, reject contributions, restrict participation, or report serious platform-policy violations. Enforcement should be proportionate to severity and repeated behavior.

Good-faith technical disagreement, criticism of code, and security review are welcome. Enforcement is about conduct, not requiring agreement.

## Reporting conduct concerns

For a private conduct concern, contact `supportramsandesh@gmail.com` with enough context to investigate. Do not include unrelated private data.

Security vulnerabilities should instead follow [SECURITY.md](SECURITY.md).
